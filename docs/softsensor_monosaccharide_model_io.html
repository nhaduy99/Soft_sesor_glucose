Soft Sensor Model Inputs and Outputs for Monosaccharide Prediction

This note translates the Emilie SoftSensor data-description files into a modelling plan for predicting monosaccharide concentrations, especially rhamnose, xylose, and glucose, from EEM and Raman spectroscopy.

Source folder read: Emilie_SoftSensor/Data_descriptions. Generated for the Codex inventory project.

Executive Model Definition

The soft sensor should learn a regression function from spectroscopy and metadata-linked sample identifiers to a numeric monosaccharide concentration vector.

Element Definition for this project
Input samples One well/sample identified by experiment, plate, well, modality, filename, and metadata.
EEM input A 15 row x 19 column excitation-emission matrix. Rows are excitation wavelengths, columns are emission wavelengths, values are fluorescence intensity. Values marked OVER exceed detector linear range and must be masked or treated as unreliable.
Raman input A two-column Raman spectrum: Raman shift in cm-1 and Raman intensity. Files span 99-3500 cm-1, but the useful measured range is described as 500-2000 cm-1. Excitation wavelength was 532 nm.
Target output Numeric monosaccharide concentrations, preferably as a multi-output vector [Rhamnose_gL, Xylose_gL, Glucose_gL]. If only one target is available, train one model per sugar.
Calibration source Known standards from Experiment 4 and quantitative HPLC reference tables when available. The data description states standard concentrations are in g/L.
Important limitation: the existing inventory notes indicate that a full quantitative HPLC target table is still the main blocker for supervised culture-sample modelling. Standards can calibrate and validate sugar signal, but final soft-sensor training needs numeric target concentrations matched to sample IDs.

Whole-System Input and Output Diagram

The spectroscopy files provide raw signals. The metadata and legends map those signals to experiment, plate, well, standard mixture, culture state, OD750, and HPLC sample codes. The final training table must align all of these fields to numeric sugar targets.

Model Candidates

Model Input Feature representation Regressor Output Purpose
Model 1: EEM PARAFAC + regression EEM only PARAFAC component scores PLSR, SVR, or XGBoost One sugar or multi-output sugar concentration vector Most interpretable EEM soft sensor. Links prediction to fluorescence components.
Model 2: Unfolded EEM + PLSR EEM only Flattened 15 x 19 matrix after masking/scaling PLSR Monosaccharide concentration Strong, simple, accepted baseline for EEM prediction.
Model 3: Unfolded EEM + nonlinear model EEM only Flattened EEM, then PCA or feature selection SVR, XGBoost, or ANN Monosaccharide concentration Use when sample size is large enough to justify nonlinear fitting.
Model 4: Raman + EEM fusion Raman plus EEM Raman PLS scores plus EEM PARAFAC scores or unfolded EEM features PLSR, SVR, XGBoost, or stacked regression Rhamnose, xylose, glucose concentrations Most powerful and most defensible direction for weakly fluorescent sugars.

Recommended Mid-Level Fusion Model

Because glucose and some monosaccharides are weakly fluorescent, EEM should not be treated as the only direct sugar sensor. Raman is better positioned for direct sugar signatures, while EEM can capture indirect metabolic and process-state changes from fluorescence-active compounds in the culture.

Recommended paper-ready result: compare Raman-only, EEM-only, and fused models, then emphasize Raman + EEM mid-level fusion if it improves prediction while retaining interpretable Raman latent variables and PARAFAC fluorescence components.

Training Table Structure

The practical output of preprocessing should be a single supervised table. Each row is one matched sample or well. Each target column is a measured or known concentration.

Column group Examples Use
Identifiers sample_id, experiment, plate, well, eem_file, raman_file Join spectroscopy with metadata and prevent leakage across replicated wells or experiments.
Metadata strain, CorE, comment, OD750, HPLC_sample_code Audit sample context and define grouped validation.
Raman features raman_pls_1 ... raman_pls_k or selected Raman intensities Direct monosaccharide spectral information.
EEM features parafac_comp_1 ... parafac_comp_k, or unfolded EEM pixels Fluorescence component/process-state information.
Targets rhamnose_gL, xylose_gL, glucose_gL Regression outputs. Use known standard concentrations and quantitative HPLC targets.

Validation and Reporting

Validation split

Use grouped validation by experiment, plate, batch, or HPLC sample group. Random row splits can overstate performance when adjacent wells or replicates are similar.

Metrics

Report RMSE, MAE, R2, bias, and predicted-vs-measured plots for each sugar. For multi-output models, report per-target metrics.

Interpretation

Use Raman loadings and PARAFAC emission/excitation profiles to explain whether predictions reflect direct sugar peaks, matrix effects, or biological process state.

Recommended Execution Order

  1. Build a matched sample table from filename, experiment, plate, well, and HPLC sample code.
  2. Add numeric target concentrations from standards and quantitative HPLC results.
  3. Preprocess EEM by masking OVER values and scatter-dominated regions; scale intensities.
  4. Preprocess Raman by cropping to 500-2000 cm-1, correcting baseline if needed, and scaling.
  5. Train Raman-PLSR as the direct-signal baseline.
  6. Train EEM-PARAFAC-PLSR for interpretability.
  7. Train EEM-unfolded-PLSR as the EEM predictive baseline.
  8. Train Raman + EEM mid-level fusion and compare against all single-modality baselines.
